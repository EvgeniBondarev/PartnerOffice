# PartnerOffice: фронтенд партнёра

React 19 + TypeScript + Vite. Внешний вид целиком использует ресурсы из [`../design`](../design/README.md): токены, шрифт Onest, иконки и CSS компонентов (кнопка, поле, информер). Своих цветов и градиентов нет.

Управления партнёрами здесь нет: учётные записи, правила и права задаёт владелец в Studio2 (`/PartnerOffice/Partners`). Приложение работает по API Studio2: Swagger-документ «PartnerOffice API» (`/swagger`).

## Запуск

```bash
cd web
npm install
npm run dev        # http://localhost:5173 (другой порт: PORT=5183 npm run dev)
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с прокси на локальную Studio2 |
| `npm test` | тесты (vitest, testing-library) |
| `npm run typecheck` | проверка типов |
| `npm run build` | типы и сборка в `dist/` |

## API: разработка и прод

| Среда | Адрес API | Как задан |
|---|---|---|
| Разработка | `http://localhost:5012` (локальная Studio2) | Vite проксирует `/partner-api` на `STUDIO2_URL`, по умолчанию `http://localhost:5012`; `VITE_API_BASE_URL` пуст |
| Прод | `https://partner-office.mpsuper.ru`, API на том же адресе | nginx контейнера проксирует `/partner-api` в Studio2, `VITE_API_BASE_URL` пустой (см. [docs/DEPLOY.md](../docs/DEPLOY.md)) |

Своё значение на время разработки: файл `.env.local` (в git не попадает), например `VITE_API_BASE_URL=https://studio2.mpsuper.ru`, чтобы смотреть интерфейс на данных прода.

Сессия партнёра живёт в cookie `.PartnerOffice.Auth` (HttpOnly, `SameSite=Strict`), токены в браузере не хранятся. И в разработке (прокси Vite), и на проде (nginx контейнера) запросы идут на тот же origin, поэтому cookie работает без CORS. Если когда-нибудь фронтенд и API разойдутся по разным адресам, потребуется CORS с cookie в Studio2.

## Структура

```
src/
  api/        клиент (ошибки, cookie) и методы авторизации
  auth/       AuthContext (сессия), RequireAuth (защита маршрутов)
  lib/        валидация (правила как на сервере Studio2)
  pages/      LoginPage, HomePage (заглушка до раздела заказов)
  ui/         Button, TextField, Informer, Icon: тонкие обёртки над CSS дизайн-системы
  styles/     подключение дизайн-системы и app.css (только токены)
  test/       тесты
```

## Раздел «Заказы» (`/orders`)

Страница содержит заголовок, фильтры, «Найдено: N» и таблицу. Данные доступны только по правилам владельца (`GET /partner-api/orders`).

- **Таблица** прокручивается внутри страницы, шапка закреплена; следующие 50 заказов подгружаются при прокрутке к концу списка (запасная кнопка «Показать ещё» для клавиатуры). Фильтры меняют набор целиком.
- **Колонки:** фото, товар (артикул с кодом бренда, как `122RU19=HSH`, бренд), номер отправления и ScanIt, статус и статус Ozon, склад и клиент, «Отгрузить до» (просрочка красным под датой) и «Принят», количество и цена, действия.
- **Фильтры:** поиск (номер, товар, артикул, ScanIt, трек-номер), статус, склад, клиент, период. Применяются кнопкой «Найти» или Enter, лежат в адресе (`?search=…&status=…`): ссылку можно отправить, «Назад» возвращает вид; сброс иконкой.
- **Фото:** в таблице уменьшенные (`ir.ozone.ru/…/c100/…`), по клику крупный просмотр (c800) поверх страницы; Esc, клик по фону и крестик закрывают.
- **Карточка заказа** в боковой панели по клику на строку: ScanIt, штрихкод товара, город доставки, даты, статус Ozon.
- **Действия** только для заказов Ozon и только то, что включил владелец:
  - «Отгрузить» (возможность «Сборка и отгрузка»): подтверждение, проверка требований Ozon, отгрузка;
  - «Этикетка» (возможность «Печать этикетки»): готовая из хранилища печатается сразу, новая запрашивается у Ozon; PDF открывается в новой вкладке и по ссылке в сообщении;
  - если Ozon просит страну-изготовителя или данные маркировки (Честный ЗНАК, ГТД, РНПТ), показывается форма с проверкой полей, данные сохраняются в Ozon и действие продолжается.
- **Сообщения** о результате и причины отказа Ozon показываются над таблицей и закрываются крестиком.
- **Меню** слева сворачивается (на окнах уже 1440px по умолчанию свёрнуто, выбор запоминается).

## Страница входа

Карточка по центру на светлом фоне, как в образце, но с нашими названием и логотипом-заглушкой «PO» (логотип Ozon использовать нельзя). Поведение:

Вход в два шага, без логина и пароля:

1. **Почта.** Проверка при уходе с поля; пока ошибка показана, значение перепроверяется на каждый символ, и ошибка пропадает сразу, как поле исправлено. Правила зеркалят серверные (`lib/validation.ts`, Studio2 `PartnerEmail`). При вводе почты название партнёра не подсказывается: форма не должна выдавать, какие почты заведены. «Получить код» отправляет `POST /partner-api/auth/code/request`.
2. **Код.** Над полем показывается «Партнёр: …» (`POST /partner-api/auth/lookup`, один запрос при переходе на шаг), чтобы человек убедился, что код придёт для нужного кабинета; для незнакомой почты строки нет и ошибки нет. Поле из шести ячеек (`ui/CodeField.tsx`): цифры вводятся подряд с автопереходом, Backspace стирает назад, стрелки переключают ячейки, вставка из буфера раскладывает код по ячейкам, автоподстановка кода из письма (`autocomplete="one-time-code"`) тоже работает. Кнопки «Войти» нет: вход отправляется сам, как только введена шестая цифра, пока идёт проверка поле заблокировано и показано «Проверяем код…». При любой неудаче поле очищается и ждёт новый ввод. «Отправить код ещё раз» включается через 60 секунд (таймер на странице), «Изменить почту» возвращает на первый шаг.

Ссылка из пригласительного письма `/login?email=…&code=…`: форма открывается на втором шаге, показывает партнёра и сразу входит по коду из ссылки (один раз, повторной отправки при перерисовках нет). Если код не подошёл, видна ошибка и пустое поле. Параметры убираются из адресной строки.

Остальное:

- ошибки с значком и текстом, не только цветом; `aria-invalid`, `aria-describedby`, фокус на первое неверное поле;
- 401: «Неверный или просроченный код» (не раскрывает, что именно не так), поле кода очищается, фокус в нём;
- 429: сообщение о блокировке после неверных кодов с временем окончания, кнопка отключена до его конца; если код запрашивали меньше минуты назад, показывается ввод кода и таймер;
- 503 при отправке письма и нет связи: информер с понятным текстом, остаёмся на первом шаге;
- «Не могу войти»: объясняет, что приглашение отправляет владелец.

## Локальный тестовый партнёр

Для проверки входа на локальной Studio2 нужен партнёр с почтой, к которой у вас есть доступ: создайте его в `/PartnerOffice/Partners` (приглашение придёт с адреса из `SmtpSettings`). Файлы `web/dev-credentials.local` и `web/prod-credentials.local` остались от входа по паролю и больше не используются.
