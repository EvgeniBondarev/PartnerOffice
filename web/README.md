# PartnerOffice: фронтенд партнёра

React 19 + TypeScript + Vite. Внешний вид целиком из дизайн-системы [`../design`](../design/README.md): токены, шрифт Onest, иконки, CSS компонентов (кнопка, поле, информер). Своих цветов и градиентов нет, правила брендбука: [`design/brandbook`](../design/brandbook/index.html#rules).

Управления партнёрами здесь нет: учётные записи, правила и права задаёт владелец в Studio2 (`/PartnerOffice/Partners`). Приложение работает по API Studio2: Swagger-документ «PartnerOffice API» (`/swagger`).

## Запуск

```bash
cd web
npm install
npm run dev        # http://localhost:5173 (другой порт: PORT=5183 npm run dev)
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с прокси на локальную Studio2 |
| `npm test` | тесты (vitest, testing-library) |
| `npm run typecheck` | проверка типов |
| `npm run build` | типы и сборка в `dist/` |

## API: разработка и прод

| Среда | Адрес API | Как задан |
|---|---|---|
| Разработка | `http://localhost:5012` (локальная Studio2) | Vite проксирует `/partner-api` на `STUDIO2_URL`, по умолчанию `http://localhost:5012`; `VITE_API_BASE_URL` пуст |
| Прод | `https://studio2.mpsuper.ru` | `VITE_API_BASE_URL` в `.env.production` |

Своё значение на время разработки: файл `.env.local` (в git не попадает), например `VITE_API_BASE_URL=https://studio2.mpsuper.ru`, чтобы смотреть интерфейс на данных прода.

Сессия партнёра живёт в cookie `.PartnerOffice.Auth` (HttpOnly, `SameSite=Strict`), токены в браузере не хранятся. В разработке запросы идут через прокси на тот же origin, поэтому cookie работает. **На проде фронтенд должен быть на том же сайте, что и API** (например, поддомен `mpsuper.ru`, либо тот же домен с проксированием `/partner-api`), и Studio2 должна разрешать CORS с cookie для адреса фронтенда. Пока в Studio2 такой настройки нет: она добавляется при выборе адреса фронтенда на проде.

## Структура

```
src/
  api/        клиент (ошибки, cookie) и методы авторизации
  auth/       AuthContext (сессия), RequireAuth (защита маршрутов)
  lib/        валидация (правила как на сервере Studio2)
  pages/      LoginPage, HomePage (заглушка до раздела заказов)
  ui/         Button, TextField, Informer, Icon: тонкие обёртки над CSS дизайн-системы
  styles/     подключение дизайн-системы и app.css (только токены)
  test/       тесты
```

## Страница входа

Карточка по центру на светлом фоне, как в образце, но с нашими названием и логотипом-заглушкой «PO» (логотип Ozon использовать нельзя). Поведение:

- проверка поля при уходе с него; пока ошибка показана, значение перепроверяется на каждый символ, и ошибка пропадает сразу, как поле исправлено;
- ошибки с значком и текстом, не только цветом; `aria-invalid`, `aria-describedby`, фокус на первое неверное поле;
- подсказки под полями, «показать пароль», предупреждение о Caps Lock;
- 401: «Неверный логин или пароль» (не раскрывает, что именно неверно), пароль очищается, фокус в нём;
- 429: сообщение о временной блокировке с временем, кнопка отключена до его конца;
- нет связи или сбой сервера: информер с понятным текстом;
- «Не могу войти»: объясняет, что учётную запись и пароль задаёт владелец.
